# 키즈오아시스 — 분당 나들이 코스 추천 MVP 프로토타입 (Stage 1~3)

`MVP-기획서`의 5단계 로드맵 중 **1~3단계**를 실제로 동작하는 코드로 구현한 프로토타입입니다.

- **Stage 1 — 데이터 확보**: 유가크루 · 다이닝코드 2곳만 샘플로 수집 (아래 "왜 2곳만, 왜 시드 데이터인지" 참고)
- **Stage 2 — 카카오맵 연동 & 검색/필터**: 지도 표시, 카테고리 · 연령 · 시간 필터
- **Stage 3 — 코스 추천 로직 & 스케줄링 UI**: 규칙 기반 반나절 코스 조합, 타임라인 UI

```
bundang-outing-mvp/
├── crawler/            # Stage 1 — 샘플 크롤러
│   ├── crawl_yugacrew.py
│   ├── crawl_diningcode.py
│   ├── merge_and_normalize.py
│   └── output/places.json   # 웹앱이 읽는 최종 데이터 (12곳 시드)
└── web/                # Stage 2~3 — React(Vite) 웹앱
    └── src/...
```

## 빠르게 실행해보기

```bash
cd web
npm install
cp .env.example .env        # 이후 .env 파일을 열어 카카오 JS 키를 붙여넣기
npm run dev                 # http://localhost:5173
```

## 1. 카카오맵 API 키 설정 (필수)

지도 · 필터 · 코스 추천이 전부 카카오맵 SDK(위치 지오코딩 포함)에 의존하므로, 키가 없으면 지도 영역에 안내 메시지만 뜨고 "코스 추천받기" 버튼도 비활성화됩니다.

1. [카카오 디벨로퍼스](https://developers.kakao.com/console/app) 접속 → 앱 선택(또는 새 앱 생성)
2. **앱 키 > JavaScript 키** 복사
3. **플랫폼 > Web** 에 실행할 도메인 등록
   - 로컬 개발: `http://localhost:5173`
   - 배포 후: 실제 서비스 도메인 추가
4. **제품 설정 > 지도** 활성화 확인
5. `web/.env` 파일의 `VITE_KAKAO_JS_KEY` 에 키 붙여넣기

> 이 프로토타입은 별도 서버 없이 **카카오맵 JS SDK의 `services` 라이브러리(클라이언트 지오코더)** 로 주소→좌표 변환까지 처리합니다. REST API 키나 백엔드 서버 없이 JS 키 하나로 동작합니다.

## 2. Stage 1 — 왜 2곳만, 왜 "시드 데이터"인지

기획서 §4 "초기 데이터 확보 전략"에서 정한 대로, 이번 단계는 **크롤링 파이프라인 자체가 동작하는지** 확인하는 것이 목적이라 전체 소스 목록(§4.4)을 다 연결하지 않고 2곳만 우선 연결했습니다.

- `crawl_yugacrew.py` — 유가크루 크루레터(나들이 큐레이션 매체) 기사에서 소제목 단위로 장소를 추출
- `crawl_diningcode.py` — 다이닝코드 "분당구 키즈카페" 검색 결과의 메타 설명에서 업체명 · 평점을 추출

**실행 관련 중요 안내**: 이 프로젝트를 개발한 샌드박스 환경은 조직 네트워크 정책상 외부 사이트로의 아웃바운드 접속이 npm 레지스트리 등 허용 목록으로 제한되어 있어, 두 스크립트를 이 환경에서 직접 실행하지는 못했습니다. 대신 개발 세션에서 두 소스를 1회 조회해 얻은 실제 결과를 사람이 정리해 `crawler/output/places.json` 에 시드로 넣어두었습니다 (총 12곳 — 나들이장소 7 · 놀이공간 3 · 식당/카페 2).

즉:
- `crawler/output/places.json` = **지금 웹앱이 쓰는 실제 데이터** (실제 조회 결과 기반, 정상 동작 확인됨)
- `crawl_yugacrew.py` / `crawl_diningcode.py` = **인터넷 접근이 열려 있는 환경(로컬 PC, 서버)에서 실행하면 위 데이터를 재현·갱신할 수 있는 실제 코드**. 사이트 구조가 바뀌었을 수 있으니 실행 전 브라우저 개발자도구로 셀렉터를 한 번 확인하는 걸 권장합니다.
- 새 소스를 추가하려면 같은 패턴으로 `crawl_*.py` 를 하나 더 만들고 `merge_and_normalize.py` 로 병합하면 됩니다.

일부 장소(다이닝코드 3곳)는 주소가 없어 `data_quality: "partial"` 로 표시되어 있고, 지도에는 표시되지 않습니다 (장소 목록에는 "정보 보강 필요" 배지로 노출). 기획서 §4.3 "데이터 품질 관리"에서 언급한 상황을 그대로 데모에 반영한 것입니다.

## 3. Stage 2 — 지도 · 필터

- `src/components/MapView.jsx` — 카카오맵 초기화, 마커 표시, 마커 클릭 시 정보창
- `src/lib/geocode.js` — 주소 → 좌표 클라이언트 지오코딩 (카카오 Geocoder)
- `src/components/FilterBar.jsx` — 카테고리(4종) · 연령 · 출발시각 · 여유시간 필터

## 4. Stage 3 — 코스 추천 로직 · 타임라인

- `src/lib/courseEngine.js` — 규칙 기반 코스 조합 엔진
  - 활동(나들이장소 · 놀이공간 · 원데이클래스) 1곳을 축으로,
  - 반경 내 가장 가까운 식당/카페를 붙이고,
  - 남는 시간이 45분 이상이면 활동을 하나 더 붙여 최대 3-스탑 코스를 만듭니다.
  - 이동시간은 두 지점 간 직선거리(haversine) 기준 평균 25km/h 로 추정합니다 (실제 도로 기반 이동시간 API는 다음 단계에서 카카오모빌리티 등으로 고도화 권장).
- `src/components/CourseTimeline.jsx` — 코스별 시작~종료 시각 타임라인 표시

## 다음 단계 제안 (Stage 4~5)

- Stage 4(클로즈드 베타) 전에: §4.4의 나머지 소스(솜씨당 · 렛츠플레이 제휴 등) 연결로 커버리지 확대
- 이동시간 추정을 카카오모빌리티 길찾기 API로 교체 (현재는 직선거리 근사치)
- 코스 저장 · 공유, 사용자 피드백(선택률) 수집 — Stage 4 클로즈드 베타 설계에 반영
